## 1. 文档概述

### 1.1 项目背景

本系统旨在为应用提供完善的用户权限管理能力，通过部门、权限、角色、用户四个维度的管理，实现精细化的访问控制。

### 1.2 核心概念

| 概念 | 说明 |
|------|------|
| **部门** | 组织架构的层级结构，用于组织用户 |
| **权限** | 对系统功能的访问控制点，对应一级菜单 |
| **角色** | 权限的集合，是权限的打包载体 |
| **用户** | 系统的实际使用者，关联部门和角色 |

### 1.3 权限模型

采用 **RBAC (Role-Based Access Control)** 模型：

```
用户 ←→ 角色 ←→ 权限 ←→ 资源(菜单)
  ↓
部门
```

## 2. 功能模块

### 2.1 部门管理

#### 2.1.1 功能描述

管理部门组织架构的树形结构，支持对部门节点进行完整的生命周期管理。

#### 2.1.2 功能列表

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 部门列表 | 以树形结构展示所有部门 | P0 |
| 新增部门 | 在指定父节点下创建子部门 | P0 |
| 编辑部门 | 修改部门名称、排序等信息 | P0 |
| 删除部门 | 删除无子部门且无用户的部门节点 | P0 |
| 启用/禁用 | 控制部门的可用状态 | P0 |
| 部门详情 | 查看部门基本信息及下属用户 | P1 |

#### 2.1.3 部门数据结构

```typescript
interface Department {
  id: string;              // 部门ID
  name: string;            // 部门名称
  parentId: string | null; // 父部门ID，null表示根部门
  sort: number;            // 排序序号
  status: 'enabled' | 'disabled'; // 状态
  createdAt: Date;         // 创建时间
  updatedAt: Date;         // 更新时间
}
```

#### 2.1.4 业务规则

1. **树形结构规则**
   - 支持多级嵌套，无层级限制
   - 每个部门有唯一的父部门（根部门除外）
   - 部门编码路径用于快速定位

2. **删除限制**
   - 存在子部门的部门不可删除
   - 存在关联用户的部门不可删除
   - 删除前需进行二次确认

3. **状态影响**
   - 禁用部门后，其下所有子部门自动禁用
   - 禁用部门后，该部门用户仍保留但无法被新用户选择

### 2.2 权限管理

#### 2.2.1 功能描述

将系统中所有一级菜单纳入权限管理，控制用户对菜单页面的访问权限。

#### 2.2.2 功能列表

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 权限列表 | 展示系统所有权限点 | P0 |
| 权限同步 | 自动扫描并同步系统菜单 | P0 |
| 权限详情 | 查看权限关联的角色和用户 | P1 |

#### 2.2.3 权限数据结构

```typescript
interface Permission {
  id: string;           // 权限ID
  code: string;         // 权限编码 (唯一)
  name: string;         // 权限名称
  type: 'menu';         // 权限类型 (当前仅支持菜单)
  menuId: string;       // 关联菜单ID
  menuPath: string;     // 菜单路由路径
  icon: string;         // 菜单图标
  description: string;  // 权限描述
  status: 'enabled' | 'disabled';
  createdAt: Date;
  updatedAt: Date;
}
```

#### 2.2.4 业务规则

1. **权限来源**
   - 权限由系统自动从路由配置中同步生成
   - 一级菜单自动生成对应权限点
   - 权限编码格式：`menu:{path}`

2. **权限控制**
   - 用户拥有权限才显示对应菜单
   - 直接访问无权限页面时重定向到403页面
   - 超级管理员拥有所有权限

3. **同步机制**
   - 系统启动时自动同步
   - 菜单变更后手动触发同步
   - 新增菜单默认启用

#### 2.2.5 系统默认权限

| 权限编码 | 权限名称 | 说明 |
|----------|----------|------|
| menu:dashboard | 数据看板 | 首页数据概览 |
| menu:department | 部门管理 | 部门组织架构管理 |
| menu:permission | 权限管理 | 系统权限点管理 |
| menu:role | 角色管理 | 角色及权限分配 |
| menu:user | 用户管理 | 用户账号管理 |
| menu:register-audit | 注册审核 | 用户注册申请审核 |
| menu:system | 系统设置 | 系统基础配置 |

### 2.3 角色管理

#### 2.3.1 功能描述

将权限点打包成角色，通过角色批量分配权限给用户。

#### 2.3.2 功能列表

| 编辑角色 | 修改角色信息及权限 | P0 |
| 删除角色 | 删除未被使用的角色 | P0 |
| 启用/禁用 | 控制角色的可用状态 | P0 |
| 角色详情 | 查看角色基本信息及权限列表 | P1 |
| 权限分配 | 为角色勾选权限点 | P0 |

#### 2.3.3 角色数据结构

```typescript

  updatedAt: Date;
}

interface RolePermission {
  id: string;
  roleId: string;          // 角色ID
  permissionId: string;    // 权限ID
}
```

#### 2.3.4 系统内置角色

| 角色编码 | 角色名称 | 默认权限 | 说明 |
|----------|----------|----------|------|
| super_admin | 超级管理员 | 全部权限 | 系统内置，不可删除 |
| admin | 管理员 | 除系统设置外的所有权限 | 系统内置，不可删除 |
| department_manager | 部门主管 | 本部门用户查看 | 系统内置 |
| user | 普通用户 | 仅数据看板 | 系统内置，默认角色 |

#### 2.3.5 业务规则

1. **角色编码**
   - 系统内置角色编码不可修改
   - 自定义角色编码需唯一
   - 编码格式：小写字母+下划线

2. **删除限制**
   - 系统内置角色不可删除
   - 已关联用户的角色不可删除
   - 删除前需确认影响范围

3. **权限继承**
   - 角色权限变更实时生效
   - 已登录用户权限在下次请求时更新

### 2.4 用户管理

#### 2.4.1 功能描述

对系统用户进行完整的生命周期管理，包括部门关联和角色分配。

#### 2.4.2 功能列表

#### 2.4.3 用户数据结构


#### 2.4.4 用户状态说明

| 状态 | 说明 | 可登录 |
|------|------|--------|
| enabled | 已启用 | ✅ |
| disabled | 已禁用 | ❌ |
| pending | 待审核 | ❌ |

#### 2.4.5 业务规则

1. **用户名规则**
   - 唯一，不可重复
   - 长度 4-20 个字符
   - 支持字母、数字、下划线
   - 创建后不可修改

2. **密码规则**
   - 长度 6-20 个字符
   - 必须包含字母和数字
   - 默认密码：`User@123`
   - 首次登录建议修改密码

3. **部门关联**
   - 每个用户必须关联一个部门
   - 部门变更时保留历史记录
   - 禁用部门不可选择

4. **角色关联**
   - 每个用户至少关联一个角色
   - 支持多角色，权限取并集
   - 禁用角色不可选择

5. **删除限制**
   - 超级管理员不可删除
   - 删除后用户数据标记为已删除，保留记录

### 2.5 用户登录

#### 2.5.1 功能描述

用户必须经过身份验证才能进入系统，系统根据用户角色控制其访问权限。

#### 2.5.2 登录流程

```
┌─────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────┐
│ 用户输入 │ → │ 校验用户名   │ → │ 校验密码    │ → │ 校验状态 │
│ 登录信息 │    │ 密码        │    │ 是否正确    │    │ 是否启用 │
└─────────┘    └─────────────┘    └─────────────┘    └─────────┘
                                                           ↓
┌─────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────┐
│ 进入系统 │ ← │ 加载用户权限 │ ← │ 生成Token   │ ← │ 更新登录 │
│ 首页    │    │ 和菜单      │    │             │    │ 信息    │
└─────────┘    └─────────────┘    └─────────────┘    └─────────┘
```

#### 2.5.3 功能列表

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 账号密码登录 | 用户名+密码登录 | P0 |
| 记住我 | 7天内自动登录 | P1 |
| 验证码 | 图形验证码防暴力破解 | P0 |
| 登录失败锁定 | 连续5次失败锁定30分钟 | P1 |
| Token刷新 | 自动续期Token | P0 |
| 登出 | 安全退出系统 | P0 |

#### 2.5.4 登录接口

```typescript
// 登录请求
interface LoginRequest {
  username: string;      // 用户名
  password: string;      // 密码 (RSA加密传输)
  captcha: string;       // 验证码
  captchaKey: string;    // 验证码标识
  remember: boolean;     // 记住我
}

// 登录响应
interface LoginResponse {
  token: string;         // JWT Token
  refreshToken: string;  // 刷新Token
  expiresIn: number;     // Token有效期(秒)
  user: UserInfo;        // 用户信息
  permissions: string[]; // 权限编码列表
  menus: Menu[];         // 可访问菜单列表
}

interface UserInfo {
  id: string;
  username: string;
  nickname: string;
  avatar: string;
  departmentName: string;
  roles: string[];
}
```

#### 2.5.5 业务规则

1. **密码传输**
   - 密码使用RSA公钥加密后传输
   - 服务端使用私钥解密后校验

2. **Token机制**
   - Access Token 有效期2小时
   - Refresh Token 有效期7天
   - Token包含用户ID和权限信息

3. **登录安全**
   - 连续5次登录失败锁定账号30分钟
   - 登录成功后清除失败次数
   - 记录登录日志（时间、IP、设备）

4. **权限加载**
   - 登录时根据用户角色加载权限列表
   - 根据权限列表生成可访问菜单
   - 前端根据菜单渲染导航

### 2.6 用户注册

#### 2.6.1 功能描述

用户可以在登录页面申请注册，填写基本信息后提交审核。有权限的用户在后台审核时分配部门和角色。

#### 2.6.2 注册流程

```
┌─────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────┐
│ 用户填写 │ → │ 校验信息    │ → │ 提交注册    │ → │ 等待审核 │
│ 注册信息 │    │ 格式合法性  │    │ 申请        │    │         │
└─────────┘    └─────────────┘    └─────────────┘    └─────────┘
                                                           ↓
┌─────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────┐
│ 审核通过 │ ← │ 管理员审核  │ ← │ 收到审核    │ ← │ 系统通知 │
│ 用户登录 │    │ 分配部门角色│    │ 通知        │    │ 管理员  │
└─────────┘    └─────────────┘    └─────────────┘    └─────────┘
```

#### 2.6.3 功能列表

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 注册申请 | 填写信息提交注册 | P0 |
| 信息校验 | 用户名/邮箱/手机号唯一性校验 | P0 |
| 审核列表 | 查看待审核和已审核记录 | P0 |
| 审核处理 | 通过/拒绝注册申请 | P0 |
| 部门分配 | 审核时选择所属部门 | P0 |
| 角色分配 | 审核时分配角色 | P0 |
| 通知提醒 | 审核结果通知申请人 | P1 |

#### 2.6.4 注册数据结构

```typescript
interface RegisterRequest {
  username: string;      // 用户名
  password: string;      // 密码
  confirmPassword: string; // 确认密码
  nickname: string;      // 昵称
  email: string;         // 邮箱
  phone: string;         // 手机号
  captcha: string;       // 验证码
  captchaKey: string;    // 验证码标识
}

interface RegisterAudit {
  id: string;
  userId: string;        // 关联用户ID
  applyInfo: {           // 申请信息
    username: string;
    nickname: string;
    email: string;
    phone: string;
  };
  status: 'pending' | 'approved' | 'rejected'; // 审核状态
  departmentId: string;  // 分配部门ID
  roleIds: string[];     // 分配角色ID列表
  auditorId: string;     // 审核人ID
  auditRemark: string;   // 审核备注
  createdAt: Date;       // 申请时间
  auditedAt: Date;       // 审核时间
}
```

#### 2.6.5 业务规则

1. **注册信息校验**
   - 用户名：4-20字符，字母数字下划线，唯一
   - 密码：6-20字符，必须含字母和数字
   - 确认密码必须与密码一致
   - 邮箱格式正确，唯一
   - 手机号格式正确，唯一

2. **审核权限**
   - 拥有 `menu:register-audit` 权限的用户可审核
   - 超级管理员自动拥有审核权限
   - 审核人不可审核自己的申请

3. **审核流程**
   - 通过：设置用户状态为enabled，分配部门和角色
   - 拒绝：设置用户状态为disabled，记录拒绝原因
   - 审核后发送通知给申请人

4. **默认设置**
   - 审核通过默认密码：`User@123`
   - 默认角色：普通用户(user)
   - 必须指定所属部门

## 5. 安全设计

### 5.1 认证安全

1. **密码加密**
   - 传输：RSA公钥加密
   - 存储：BCrypt哈希加密
   - 密码强度：至少6位，包含字母和数字

2. **Token安全**
   - JWT Token签名验证
   - Access Token 2小时有效期
   - Refresh Token 7天有效期
   - Token黑名单机制

3. **登录安全**
   - 图形验证码防暴力破解
   - 登录失败锁定机制
   - 登录IP和设备记录

### 5.2 接口安全

1. **权限校验**
   - 所有管理接口需登录
   - 接口级别权限控制
   - 数据级别权限隔离

2. **请求安全**
   - 防CSRF攻击
   - 防SQL注入
   - 防XSS攻击
   - 请求频率限制

### 5.3 数据安全

1. **敏感数据**
   - 密码加密存储
   - 手机号脱敏显示
   - 操作日志记录

2. **数据备份**
   - 定期数据库备份
   - 关键操作审计日志
