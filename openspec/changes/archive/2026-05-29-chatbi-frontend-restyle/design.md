## Context

DB-GPT 前端当前使用旧版导航和样式，与 ChatBI 原型风格差异较大。需要进行纯前端重构，保持功能不变、后端不变。

**当前状态：**
- 侧边栏使用单级导航，无分组
- 页面样式不统一，各管理页面风格各异
- 缺少4个新页面（我的报告、收藏夹、模板广场、团队共享）

**约束：**
- 纯前端重构，不修改后端 API
- 保持现有权限系统不变
- 兼容现有 i18n 方案

## Goals / Non-Goals

**Goals:**
- 实现 ChatBI 风格5分组导航栏
- 统一现有管理页面样式
- 开发4个新增前端静态页面
- 保持权限控制逻辑不变

**Non-Goals:**
- 不修改后端 API
- 不修改数据库结构
- 不添加新 API 接口
- 不修改业务逻辑

## Decisions

### 1. 导航组件结构
**决策：** 创建新组件 `NewSideBar.tsx`，不直接修改现有 `side-bar.tsx`
**原因：** 避免影响现有功能，允许回滚
**替代方案：** 直接修改现有组件 - 风险较高

### 2. 样式方案
**决策：** 使用 CSS 变量 + Ant Design 主题覆盖
**原因：** 现有项目使用 Ant Design 5，可通过 ConfigProvider 统一样式
**替代方案：** 全量 CSS-in-JS - 工作量大

### 3. 页面高亮实现
**决策：** 使用 Next.js `usePathname` + 权限过滤
**原因：** 与现有权限系统集成，无新增依赖
**替代方案：** React Router - 需要重构路由

### 4. 分组导航数据流
**决策：** 静态配置 + 权限过滤
**原因：** 导航结构相对稳定，权限动态变化
```typescript
const navGroups = [
  { key: 'workspace', label: '工作区', items: [...] },
  { key: 'explore', label: '探索发现', items: [...] },
  // ...
];
// 根据 hasPermission() 过滤每个 item
```

## Risks / Trade-offs

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 样式覆盖不全 | 部分组件样式不统一 | 逐步验收，专项修复 |
| 导航权限丢失 | 某些菜单项消失 | 权限 key 与侧边栏对齐 |
| 新组件与现有路由冲突 | 页面打不开 | 先在测试环境验证 |

## Migration Plan

1. **阶段一（导航）：** 创建 NewSideBar，通过 feature flag 切换
2. **阶段二（样式）：** 逐页面更新样式，先管理员页面后业务页面
3. **阶段三（新页面）：** 并行开发，验收后上线

**回滚策略：** 移除 NewSideBar，恢复 side-bar.tsx 引用
