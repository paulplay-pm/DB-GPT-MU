## 阶段一: 后端基础设施

### Task 1: 创建部门管理后端 API
**描述**:  实现部门的 CRUD API，支持树形结构查询

**验收标准**:
- [ ] 部门新增 API (POST /api/v2/sys/dept)
- [ ] 部门编辑 API (PUT /api/v2/sys/dept/{id})
- [ ] 部门删除 API (DELETE /api/v2/sys/dept/{id}) - 需检查无子部门/无用户
- [ ] 部门查询 API (GET /api/v2/sys/dept) - 返回树形结构
- [ ] 部门启用/禁用 API (PATCH /api/v2/sys/dept/{id}/toggle)
- [ ] 获取所有部门(平铺) API (GET /api/v2/sys/dept/all) - 用于下拉选择

**依赖**: SQL 迁移脚本已完成
**工作量**: 4h

---

### Task 2: 创建权限管理后端 API
**描述**: 实现权限点查询 API（权限点仅系统初始化，管理员只读）

**验收标准**:
- [ ] 获取所有权限点 API (GET /api/v2/sys/permission) - 支持树形/平铺两种格式
- [ ] 权限点仅支持查询，不支持增删改（由系统初始化）

**依赖**: SQL 迁移脚本已完成
**工作量**: 2h

---

### Task 3: 创建角色管理后端 API
**描述**: 实现角色的 CRUD 及权限关联管理

**验收标准**:
- [ ] 角色新增 API (POST /api/v2/sys/role)
- [ ] 角色编辑 API (PUT /api/v2/sys/role/{id})
- [ ] 角色删除 API (DELETE /api/v2/sys/role/{id})
- [ ] 角色查询 API (GET /api/v2/sys/role)
- [ ] 角色启用/禁用 API (PATCH /api/v2/sys/role/{id}/toggle)
- [ ] 获取角色关联权限 API (GET /api/v2/sys/role/{id}/permissions)
- [ ] 更新角色权限 API (PUT /api/v2/sys/role/{id}/permissions)

**依赖**: Task 2
**工作量**: 4h

---

### Task 4: 创建用户管理后端 API
**描述**: 实现用户的 CRUD 及角色关联管理

**验收标准**:
- [ ] 用户新增 API (POST /api/v2/sys/user)
- [ ] 用户编辑 API (PUT /api/v2/sys/user/{id})
- [ ] 用户删除 API (DELETE /api/v2/sys/user/{id}) - 超级管理员不可删除
- [ ] 用户查询 API (GET /api/v2/sys/user) - 分页+条件筛选
- [ ] 用户启用/禁用 API (PATCH /api/v2/sys/user/{id}/toggle)
- [ ] 获取用户关联角色 API (GET /api/v2/sys/user/{id}/roles)
- [ ] 更新用户角色 API (PUT /api/v2/sys/user/{id}/roles)
- [ ] 获取当前用户信息 API (GET /api/v2/sys/user/me) - 含权限列表
- [ ] 超级管理员不可通过 API 修改 is_super_admin 字段

**依赖**: Task 1, Task 3
**工作量**: 6h

---

### Task 5: 创建用户登录/登出 API
**描述**: 实现用户名密码认证及会话管理

**验收标准**:
- [ ] 登录 API (POST /api/v2/auth/login) - 校验用户名+密码，返回会话
- [ ] 登出 API (POST /api/v2/auth/logout) - 销毁会话
- [ ] 获取当前会话用户 API (GET /api/v2/auth/me) - 含权限列表
- [ ] 密码使用 bcrypt 加密验证
- [ ] 登录成功后返回用户信息(含权限列表)和 Session/Cookie
- [ ] 禁用用户禁止登录
- [ ] 登录接口添加防暴力破解（可选：限流）

**依赖**: Task 4
**工作量**: 4h

---

### Task 6: 创建用户注册申请与审核 API
**描述**: 实现用户注册申请提交流程和管理员审核流程

**验收标准**:
- [ ] 提交注册申请 API (POST /api/v2/auth/register) - 创建 pending 状态申请
- [ ] 获取注册申请列表 API (GET /api/v2/sys/registration) - 仅超级管理员可访问，分页+状态筛选
- [ ] 审核通过 API (POST /api/v2/sys/registration/{id}/approve) - 创建正式用户+分配角色+删除申请记录
- [ ] 审核拒绝 API (POST /api/v2/sys/registration/{id}/reject) - 更新状态+拒绝原因
- [ ] 申请登录名不可与已有用户重复
- [ ] 审核时必须指定部门和角色

**依赖**: Task 1, Task 3, Task 4
**工作量**: 6h
