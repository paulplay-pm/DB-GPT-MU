# 提案: 用户权限管理系统

## 摘要

为 DB-GPT 增加完整的用户权限管理能力，包括部门管理、权限管理、角色管理、用户管理、登录认证和用户注册审核六大模块。

## 背景与问题

当前 DB-GPT 系统：
- **无用户认证**：登录逻辑为 MOCK，直接放行
- **无权限控制**：所有菜单对所有用户无条件可见
- **无用户体系**：虽有 `user_code` 字段分散在各表，但无独立用户管理
- **无审核流程**：无法管理用户注册申请

## 目标

1. 实现完整的用户认证流程（登录/注册/审核）
2. 基于菜单的权限控制体系
3. 部门树形组织架构
4. 通过角色打包权限，实现细粒度访问控制
5. SQL 脚本升级现有数据库

## 范围

### 纳入范围

- 部门管理（树形结构，最多10级）
- 权限管理（系统所有一级菜单及子菜单）
- 角色管理（权限打包）
- 用户管理（CRUD + 启用/禁用）
- 用户登录认证
- 用户注册申请与审核

### 不纳入范围

- 多租户支持（单租户设计）
- 现有 `user_code` 字段迁移（新建系统独立管理）
- 审计日志（未来版本）

## 功能详述

### 1. 部门管理

- 树形结构，支持最多10级
- 字段：id(自增), code(手工输入), name, parent_id, level, sort, is_active
- 操作：新增子部门、编辑部门、删除部门（需无子部门/无用户）、启用/禁用

### 2. 权限管理

- 将系统所有菜单路径（见设计文档）纳入权限点
- 字段：id(自增), code(唯一), name, parent_code, type(menu/button/api), sort, is_active
- 操作：仅查看（权限点由系统初始化，管理员不可修改）

### 3. 角色管理

- 把权限点打包成角色
- 字段：id(自增), code, name, description, is_active
- 操作：CRUD + 启用/禁用 + 关联权限

### 4. 用户管理

- 字段：id(自增), user_id(关联其他模块), user_name(登录名), password(加密), real_name, email, dept_id, is_active, is_super_admin
- 操作：CRUD + 启用/禁用 + 关联角色
- 超级管理员：内置标记，不可删除，不可编辑角色关联

### 5. 用户登录

- 用户名+密码认证，密码 bcrypt 加密
- 登录成功返回用户信息（含权限列表）
- 所有 API 请求需携带 Token（Session/Cookie）

### 6. 用户注册与审核

- 用户提交注册申请：user_name, password, real_name, email, apply_dept_id
- 申请状态：pending → approved / rejected
- 审核通过后：创建正式用户，分配部门+角色

## 验收标准

1. SQL 脚本可在现有数据库直接运行，不影响现有数据
2. 超级管理员账户可正常登录后台
3. 前端根据用户权限动态渲染菜单
4. 未登录用户访问任意页面均跳转登录页
5. 注册申请提交后需审核通过才可登录

## 非目标

- 不修改现有 `GptsAppEntity.user_code` 等字段
- 不实现 OAuth/SSO 等第三方认证
- 不实现数据权限（行级）
- 不实现操作审计
